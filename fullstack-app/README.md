## Стек

**Frontend**

- React 19 + Vite 8
- Redux Toolkit (`createSlice`, `createAsyncThunk`)
- React Router 7
- react-hook-form + Zod (валидация форм)
- Axios (интерсепторы, `withCredentials`)
- Графики — собственные SVG-компоненты без внешних библиотек

**Backend**

- Node.js >= 22.5
- Express 5
- Встроенный модуль `node:sqlite` (не требует нативной сборки)
- JWT: access-токен (15 минут) + refresh-токен в HttpOnly cookie (7 дней)
- bcryptjs для хеширования паролей

## Что реализовано

### Авторизация

- Регистрация с валидацией (email, username, телефон, пароль)
- Вход по email **или** username
- Восстановление пароля по токену
- Восстановление сессии при перезагрузке страницы через `/auth/refresh`
- Выход с очисткой refresh-куки
- Защищённые маршруты (`ProtectedRoute`)

### Транзакции (`/transactions`)

- Добавление дохода/расхода
- Редактирование и удаление
- Поиск по описанию и категории (с дебаунсом)
- Фильтр по типу
- Пагинация
- Валидация формы на клиенте (Zod) и на сервере
- Состояния: загрузка, ошибка с кнопкой «Повторить», пустой список

### Дашборд (`/analysis`)

- Карточки: доходы, расходы, баланс, количество транзакций
- Столбчатая диаграмма доходов и расходов по месяцам
- Кольцевая диаграмма расходов по категориям
- Переключение периода: 6 месяцев / 12 месяцев / всё время
- Состояния загрузки, ошибки и отсутствия данных

### UI/UX

- Адаптивная вёрстка (мобильные, планшеты, десктоп)
- Светлая и тёмная тема (`prefers-color-scheme`)
- Единые стили кнопок, полей, таблиц, бейджей и алертов
- Навигация с шапкой и информацией о пользователе

### Администрирование (`/admin`)

Доступно только пользователям с ролью `admin` (пункт «Админка» появляется в шапке).

- Список всех пользователей с агрегатами: количество транзакций, доходы, расходы, баланс
- Блокировка и разблокировка пользователей
- Удаление пользователя вместе с его транзакциями
- Просмотр всех транзакций всех пользователей с поиском, фильтром и пагинацией
- Защита от блокировки/удаления самого себя и последнего администратора
- Заблокированный пользователь не может войти и сразу теряет доступ по уже выданному токену

### Оптимизации

- `React.memo` — строки таблицы, карточки статистики, компоненты графиков
- `useMemo` — агрегации для графиков, список страниц пагинации, максимум диаграммы
- `useCallback` — обработчики формы, редактирования, удаления, пагинации

## Главный сценарий

1. Открыть приложение и войти (или зарегистрироваться).
2. Попасть на дашборд `/analysis` — увидеть карточки и графики.
3. Перейти в `/transactions` — добавить транзакцию.
4. Найти её через поиск или фильтр, при необходимости изменить/удалить.
5. Вернуться на `/analysis` — графики пересчитаются по новым данным.

## Быстрый старт

Требуется Node.js **22.5+** (используется встроенный `node:sqlite`).

```bash
cd fullstack-app

# 1. Установка зависимостей
npm run setup

# 2. Запуск сервера (терминал 1)
npm run server

# 3. Запуск клиента (терминал 2)
npm run client
```

Клиент откроется на `http://localhost:5173`, API — на `http://localhost:5000`.
Vite проксирует запросы `/api` на Express, поэтому CORS и порт клиента не мешают.

### Установка без корневых скриптов

```bash
cd server && npm install && npm start
cd client && npm install && npm run dev
```

## Тестовый аккаунт

При первом запуске база автоматически заполняется:

- **Email:** `admin@example.com`
- **Пароль:** `admin123`

Этот аккаунт имеет роль `admin` и доступ к разделу `/admin`. Новые пользователи регистрируются с ролью `user`.

Также можно зарегистрировать нового пользователя — его транзакции изолированы от других.

## API

Базовый URL: `http://localhost:5000/api`

### Авторизация

| Метод | Путь | Описание |
| --- | --- | --- |
| `POST` | `/auth/register` | Регистрация |
| `POST` | `/auth/login` | Вход по email или username |
| `POST` | `/auth/logout` | Выход |
| `GET` | `/auth/refresh` | Восстановление сессии по refresh-куке |
| `POST` | `/auth/forgot-password` | Запрос сброса пароля |
| `POST` | `/auth/reset-password` | Установка нового пароля |
| `POST` | `/auth/activate` | Подтверждение email |
| `POST` | `/auth/resend-activation` | Повторная отправка кода |

### Транзакции (нужен `Authorization: Bearer <accessToken>`)

| Метод | Путь | Описание |
| --- | --- | --- |
| `GET` | `/transactions?page=1&limit=10&search=&type=` | Список с пагинацией, поиском и фильтром |
| `POST` | `/transactions` | Создание |
| `PUT` | `/transactions/:id` | Обновление |
| `DELETE` | `/transactions/:id` | Удаление |

Создание, изменение и удаление транзакции автоматически обновляют баланс пользователя (`users.savings`).

Пример ответа списка:

```json
{
  "data": [{ "id": 1, "amount": 500, "type": "income", "category": "Salary" }],
  "total": 1,
  "page": 1,
  "limit": 10
}
```

### Администрирование (нужен `Authorization: Bearer <accessToken>` и роль `admin`)

| Метод | Путь | Описание |
| --- | --- | --- |
| `GET` | `/admin/users` | Все пользователи с агрегатами по транзакциям |
| `GET` | `/admin/transactions?page=1&limit=20&search=&type=&userId=` | Все транзакции всех пользователей |
| `PATCH` | `/admin/users/:id/block` | Блокировка/разблокировка, тело `{ "blocked": true }` |
| `DELETE` | `/admin/users/:id` | Удаление пользователя и его транзакций |

Без токена — `401`, с токеном обычного пользователя — `403`. Заблокированный аккаунт получает `403` при входе, обновлении сессии и любых запросах с токеном.

## Особенности реализации

- **`node:sqlite`** — встроенный модуль Node, поэтому не нужны Visual Studio и нативная сборка `sqlite3`. Если проект запускается на Node < 22.5, замените адаптер в `server/db.js` на пакет `sqlite3`.
- **Access-токен** хранится в Redux и дублируется в `localStorage` (`src/app/tokenStorage.js`), чтобы axios-интерсептор мог добавлять заголовок `Authorization`. Refresh-токен — только в HttpOnly cookie.
- **Графики без зависимостей** — SVG-компоненты `BarChart` и `DonutChart` адаптируются под ширину контейнера.
- **Прокси Vite** — запросы идут на относительный `/api`, поэтому в dev-режиме нет проблем с CORS.
- **Автосоздание БД** — при старте создаются таблицы и тестовые данные, если их нет.
